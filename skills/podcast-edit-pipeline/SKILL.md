# Podcast edit pipeline
0. Get the Zencastr transcript exports (CSV + TXT) with the tracks. They are the primary text (`transcript.source: zencastr`); full ASR is only the fallback when no CSV exists.
1. Run every long step in the background (`nohup … > log 2>&1 &`) and poll; steps are resumable (rerun skips stages whose outputs exist; `RESUME=0` forces).
   `./run_pipeline.sh <ep> prep --track host=… --track guest_a=… --transcript z.csv --transcript z.txt --speaker "Name=host" …` (steps 01–04; stops on first failure).
2. Label review items (@podcast-04-cut-list), then `./run_pipeline.sh <ep> finish` (05–07).
3. When final, hand off to the Publisher bot per @podcast-07-qa-handoff: out/<slug>.mp3, out/show_notes.md, out/chapters.json, an editor-written title, publish time (default next Monday 07:00 JST + Vancouver time (PT)), the ad insertion point (pre-jingle silence start) and default artwork; the editor never uploads or publishes.
Do not change parameters in prose; edit `config.yaml` and record why in `<ep>/logs/notes.md`. Episode folders live outside the repo. Never upload, post or send.
`finish` runs build → gate → render → jingle → ending_bgm → loudness → chapters → qa. `jingle` (config `jingle`) inserts the mid-show jingle once after the sentence end and any trailing laughter/aizuchi (waited out, up to `max_tail_s`; nothing cut) (0.4 s silence → jingle → 0.2 s silence) searching the middle of the show first (`prefer_range_frac` 0.3–0.7, widening by `widen_step_frac`), within each range a clean chapter-boundary pause before the longest clean sentence-end pause; never in the first 2 min or near the ending BGM; at a chapter where the next speaker talks over the others' laugh/aizuchi tail it shifts only that speaker's track (`track_shift`, `max_shift_s` 3 s) so the tails finish before the jingle; it only adds time and shifts the timemap, and the jingle audio is never committed. `ending_bgm` (config `ending_bgm`) fades the ending BGM in shortly before the last closing phrase (「ということで」), ducked under the voices, then BGM alone for a few seconds after the last speech, a fade-out linear in dB to inaudible (`fade_out_s`, `fade_out_floor_db`) and `end_silence_s` of digital silence; it skips with a warning when disabled, the BGM file is missing or the phrase isn't found. The BGM audio is never committed; point `ending_bgm.file` at it. The gate (`pipeline/gate.py`, config `gate`) mutes each track outside its own speech (words only where VAD agrees, pads from VAD edges, sniffs = unvoiced + high-band, muted inside islands/pads/edges while word endings and voiced decays are kept, coughs/throat-clears = sudden-onset short islands with unstable pitch and no word, ≥ 0.2 s after own speech (`gate.burst_*`; onset and start-near-floor margin are relative to each track's own SNR and non-speech p90), burst-free room tone); it reuses the cleaned/levelled tracks.
Overlapping pure laughter (`candidates.overlap_laughter`) keeps one laugh and mutes only the losing speaker's pure-laughter interval (room tone; source timeline unchanged). Three speakers laughing at once keep the unique speaker whose role is neither `interviewee_role` nor `primary_host_role`; if that speaker is missing or not unique, leave the overlap for human review and mute nobody. Two-speaker overlaps have no built-in winner (`two_speaker: review`, or `role_map` plus an explicit `two_speaker_role_winners` entry). Speech, questions, ordinary backchannels, and mixed speech/laughter stay out of this rule. Role-to-track mappings live only in the episode `manifest.json` under `roles_manifest_key` (default `speaker_roles`). Extra laughter-only mutes for an episode already in review go in episode-local `laughter_edits.json` (`kind: laughter`, `action: mute`, one speaker track). `label_store.py build` appends them and does not rewrite saved labels.

`ending_bgm.mode: full_asset` plays the music payload once, from `bgm_offset_s` through EOF, and does not loop or shorten it to `tail_s` / `fade_out_s`. An optional `outro_file` is a second asset (not the mid-show jingle) and is also played in full; its end is aligned to the music end unless both `music_start_s` and `outro_start_s` are set. `end_anchor: speech_end` aims that shared end at the last qualifying VAD end (final speech). `end_anchor: episode_end` aims it at the voice-mix duration before this step extends the file (current episode end, which can be later than the last word). `end_anchor: explicit` uses episode-local `end_anchor_s`. If a full payload would start before `start_floor_s`, both assets shift later together (`end_anchor_met: false`, `anchor_shift_s`); samples are kept. Under speech the level is `bed_db`; after `gain_speech_end_s` (null = that VAD end) it rises to `tail_db` and holds through the last sample when `tail_fade_ms` is 0. `end_silence_s` is digital silence after that content. `mode: phrase_tail` remains the fixed-tail fade and is what an episode config without `mode` still does. Assets and per-episode anchors stay outside the repo.

Every skill, config or playbook change is committed in this repo and must reach GitHub: commit, then report the sha so it can be pushed (push only when access/approval exists).
